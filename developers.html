Developers

Everything the project agrees on lives in the spec repository: the data model, the JSON Schemas, the OpenAPI document, the privacy rules and the test fixtures. If an implementation and that repository disagree, that repository is right.

Nothing here is running The API is not deployed. api.wifishare.example in the OpenAPI document is a placeholder, chosen so that nobody accidentally points a client at a real host: the production address is decided when hosting is. The dump repository exists but is empty. The specification is version 1, marked draft, and nothing in it is frozen until the first public beta.

The API, version 1

Three properties are load-bearing, and any reimplementation has to keep them:

  • Contributing needs no account and carries no device identifier. A batch is encrypted with HPKE to an ingest key before it is posted, so proxies and logs never see it.
  • A lookup asks for a geohash-5 area, about 4.9 km across, so the server is never told a caller's precise position.
  • There is no endpoint that resolves a hardware address to a position, and community-found networks carry no hardware address at all.
Endpoints, from openapi.yaml
Endpoint Does Notes
GET /v1/keys Current ingest public keys, newest first Clients ship with a pinned key and refresh here. After a rotation the previous key stays valid for 30 days.
POST /v1/batches Submit an encrypted batch of observations Body is an envelope. Returns 202 with how many observations were accepted and rejected, and which rule ids refused, never which network. 409 means the key id is retired: fetch /v1/keys and resend.
GET /v1/areas/{geohash5} Published networks in one area Returns the same document as the file in the dump, as application/geo+json. Cache with the ETag: most areas change at most once a week. 404 means nothing is published there yet.
POST /v1/networks/{id}/reports Say a network works, fails, is not free, is private or is gone Anonymous and rate-limited. A free-text note is read by people, and a client has to say so.
POST /v1/optout Remove a network and keep it out A hardware address, or a network name plus an area. Accepted whether or not the network was known. No proof demanded.
POST /v1/claims Start a venue claim Returns a challenge code like ws-4f2a9c to append to the network name.
POST /v1/claims/{claim_id}/verify Confirm the code is visible on air Takes the observed name and the hardware address. 409 if the code was not seen on that network.

Errors are RFC 9457 problem details, and carry the filter or publish rule that refused when there is one. Rate limiting returns 429 with Retry-After.

The ingest envelope

HPKE (RFC 9180) base mode, suite x25519-sha256-chacha20poly1305, with info set to the batch schema id and the key id passed as additional authenticated data:

{
  "schema": "wifishare.envelope/1",
  "key_id": "2026q4",
  "suite": "x25519-sha256-chacha20poly1305",
  "enc": "<base64url, 32 bytes>",
  "ct": "<base64url>"
}

Inside it is a batch: the schema id, a client object carrying only the platform and a major.minor version, and up to 200 observations. No batch id, no sequence number and no timestamp, so two batches from one device cannot be linked.

The dump

One file per geohash-5 cell, nested under the geohash-2 and geohash-3 prefixes of the same geohash. The three segments are prefixes of one value, not three separate ones.

areas/<gh2>/<gh3>/<gh5>.geojson

Worked example

Piazza Maggiore in Bologna is at 44.4938, 11.3426. Encode that as a geohash of at least 5 characters and take the prefixes:

From a coordinate to a file path
StepValue
Coordinate44.4938, 11.3426
geohash-7srbj45g — the published cell of a community network there, about 153 m by 109 m
geohash-5srbj4 — the area, about 4.9 km
geohash-3srb — second directory
geohash-2sr — first directory
Pathareas/sr/srb/srbj4.geojson

A missing file is not an error: it means nothing is published for that area. Check the eight neighbouring cells as well when you are near a boundary, because a network just across it lives in the neighbour's file. index.json lists the areas that exist, so you can fetch that first instead of probing.

Each directory therefore holds at most 32 subdirectories or 1,024 files, which stays under GitHub's limit of 3,000 entries per directory.

What is in a file

A GeoJSON FeatureCollection with foreign members naming the cell and the licence, and one Feature per network with a Point geometry. Longitude first, as GeoJSON requires. The normative shape is area.schema.json, which references network.schema.json for the properties.

SCHEMA.md in the data repository is a readable summary of the same fields for people consuming the dump. Where the two ever disagree, the schemas in spec are what an implementation must follow.

Reading it safely

  • Do not treat a community coordinate as a location. It is a cell centre. Use precision_m and cell when precision matters.
  • Do not assume bssids is present. Code that requires it will fail on almost every feature.
  • Do not join this data against another database in a way that would restore the precision the filter removed, or re-identify a person. The three privacy rules apply to what you build on the dump, and the ODbL's share-alike terms apply to the result.
  • Do not pin to a commit in the data repository. History is squashed monthly so that removals are real. Use a monthly release if you need a fixed version.

Running your own

You can run everything yourself. That is not a courtesy: the backend is AGPL-3.0 precisely so that a modified instance stays open to the people using it.

What is possible today

  1. Serve the dump layout. An area file is a static file. Put areas/<gh2>/<gh3>/<gh5>.geojson and an index.json behind any web server, send Access-Control-Allow-Origin if a browser is going to read it, and you have a working read-only instance. The sample/ directory here is exactly that, in miniature.
  2. Point a client at it. Set DATA_BASE_URL in config.js and this site's map reads your files instead of the sample.
  3. Validate what you produce. Check every file against area.schema.json from spec before you serve it. The schema catches the mistakes that matter, including a community network carrying a hardware address or the wrong precision.
  4. Run the privacy fixtures. privacy/fixtures/filter-cases.json in spec is the acceptance test for the on-device filter. Evaluate the age rule against the fixture's now field, not the wall clock, and apply the drop rules in numeric order, reporting the first that matches. A client that keeps a network the fixtures drop is a privacy bug and must not ship.

What is not possible yet

The api repository is a Django backend that has not been written: there are no build or deployment instructions in it to link to, because there is nothing to build. Ingest, aggregation, the claim flow and the export job are phase P1 work. If you want to run a full instance, that is the part to help with rather than the part to follow instructions for.

Previewing this site

git clone https://github.com/WiFiShare/wifishare.github.io.git
cd wifishare.github.io
python3 -m http.server 8000

Then open http://localhost:8000/. There is no build step and no dependency to install: the repository is served exactly as it is. Opening the files directly with file:// will not work for the map, because a browser refuses module scripts and fetches from that scheme.
