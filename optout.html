Keep a network out

You do not need an account, an email address or a reason. If a Wi-Fi network is yours and you do not want it collected, rename it so its name ends in _nomap.

Nothing is collected yet No app has been released and the published dump is empty, so there is currently nothing to remove. Renaming a network now still works: it means the network is never collected in the first place, which is the stronger outcome.

The reliable way: rename the network

Open your router's settings page, change the network name so it ends in _nomap, and save. For example:

Casa Rossi        becomes   Casa Rossi_nomap
The Bear Cafe     becomes   The Bear Cafe_nomap

WiFiShare also honours _optout, so a name ending in either suffix is dropped. The comparison ignores case, and only the ending counts: a network called Bar Nomap is not opted out, because the name does not end in the suffix.

Everyone in your household will see the new name and will have to rejoin the network once. That is the whole cost.

It is not only WiFiShare that honours it

_nomap is not a WiFiShare invention. Google introduced it, documents it, and asks other location-service providers to respect it: "We encourage other providers to respect the _nomap tag as a way to opt out from inclusion in a Location server." Apple honours the same suffix and documents it: "The owner of a Wi-Fi access point can opt it out of Apple's Location Services by changing the access point's SSID (name) to end with _nomap." _optout came from Microsoft's service. WiFiShare accepts both.

Apple notes one limit that applies here too: the opt-out cannot work for a hidden network, because a hidden network does not broadcast its name for anyone to read. WiFiShare never collects hidden networks at all, by rule R1, so they need no opt-out.

Each provider runs its own database and decides its own rules, so renaming opts you out of the providers that honour the convention, not of every database in the world. If a specific provider matters to you, check what that provider's own documentation says today.

What the rename does here

The check happens on the phone, in the app, before anything is stored or sent. A network with one of those endings is dropped by rule R2 and never reaches the network at all. The server applies the same rule again on arrival, so an old app that got it wrong cannot sneak one through.

Removing a network that is already listed

Two more routes are planned. Neither exists yet.

  1. One tap in the app. Planned for both apps. While you are connected to a network, the app reads its hardware address and asks the server to remove it. No account, no proof. Removal is low risk, and an owner who later wants the network listed can claim it.
  2. The web form below. For when you are not on the network, or do not want to install anything. It identifies a network by its name plus the rough area it is in, because that is enough to find it and does not require you to look up anything technical.

Whichever route is used, the network is unpublished straight away and leaves the weekly dump at the next export. Its hardware address is then kept only as a keyed hash, so the network can be kept out without it being held on file.

The web form

What the form does not ask for

  • No password. Not the network's, not yours. Nothing here or anywhere else on this site will ever ask for a Wi-Fi password in order to remove a network. If a page does ask, it is not this project.
  • No account, no email address, no name. There is nothing to send you and nobody to check you against.
  • No proof of ownership. Removal is low risk: the worst outcome is a network missing from a public map, and its owner can put it back by claiming it.
  • No exact address. An area, not a location.
  • No hardware address. The app route uses one, because the phone can read it while connected. A person filling in a web form should not have to go and find it.

A network in the data that should not be there

If a listed network is not yours but should not be listed — someone's home, a network that no longer exists, a wrong position — open a Network problem issue on the data repository. Issues are public: do not include a hardware address or a password in one.

Three reports saying a network is private or gone take it out automatically, so reporting through an app will also work once there is one.
